# CloudDocs — Security & DevSecOps Specification

Security is enforced at every architectural tier of CloudDocs.

---

## 1. Authentication & Authorization

- **Password Hashing**: Industry standard bcrypt with salt rounds. Plain text passwords are never stored or logged.
- **Tokens**: Cryptographically signed JWT tokens with expiration timestamps.
- **Backend Authorization**: Role-Based Access Control (RBAC) enforced on every API route (`Owner`, `Editor`, `Commenter`, `Viewer`). The backend never trusts client-side permission claims.

---

## 2. File & Cloud Storage Protection

- **No Permanent Storage Credentials in Frontend**: The frontend never receives R2 access keys or secret keys.
- **Presigned URLs**: Signed PUT and GET URLs are cryptographically generated by the backend with short expiration windows (1 hour).
- **Safe Randomized Object Keys**: Filenames are never used as raw storage paths (`docs/{user_id}/{uuid}_{salt}.{ext}`) to prevent path traversal attacks.
- **MIME & Extension Whitelist**: Strict validation of supported extensions and file size limits (100 MB max).

---

## 3. Threat Mitigation

- **SQL Injection**: Prevented via SQLAlchemy 2.0 parameterized queries and ORM mappings.
- **Cross-Site Scripting (XSS)**: Escaped React rendering and Content Security Policy headers in Nginx.
- **Path Traversal**: Local storage abstraction normalizes all paths and rejects directory breakout attempts (`..`).
- **Audit Logging**: All security-critical actions (logins, failed logins, document uploads, downloads, permissions grants, share link creations) are persisted in the `audit_logs` table.
